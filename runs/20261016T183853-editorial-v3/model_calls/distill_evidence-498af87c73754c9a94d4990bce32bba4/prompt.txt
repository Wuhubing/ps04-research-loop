They proposed the methods, wrote the\ncode, ran the evaluations, and reproduced one another’s claims; we defined\nthe task and evaluator and wrote this account from their published\nrecord. Section [4.8](#S4.SS8) describes how we\nchecked it.\n4.1 Task and evaluator\nPretrained language models store a great deal of knowledge in their weights, but reusing it in a new architecture normally means training on data. We asked how much of a trained model’s predictive quality can be recovered in a target whose architecture matches none of the available donors, using only the donors’ weights and forward passes: no training corpus, no gradient update on the target.\nThe donor zoo holds 141 open-weight models (534 GB) from 32 architecture\nfamilies, including GPT-2, LLaMA, Mistral, Qwen, Gemma, Pythia, RWKV, and\nMamba\n([Radford et al., 2019](#bib.bib34); [Touvron et al., 2023](#bib.bib35); [Jiang et al., 2023](#bib.bib36); [Bai et al., 2023](#bib.bib48); [Gemma Team, 2024](#bib.bib49); [Biderman et al., 2023](#bib.bib50); [Peng et al., 2023](#bib.bib51); [Gu and Dao, 2023](#bib.bib43)).\nThe target is a 14-layer hybrid that alternates attention blocks\n([Vaswani et al., 2017](#bib.bib44)) with simplified Mamba-style state-space (SSM)\nblocks ([Gu and Dao, 2023](#bib.bib43)) that keep Mamba’s projections, depthwise causal\nconvolution, and gating but replace the selective scan with a data-dependent\nscalar gate, with hidden size 672, seven query heads sharing one key–value\nhead, untied embeddings, and 119,572,320 parameters. We chose these dimensions so\nthat no donor matches any of them. A participant submits a Python file with a\ntransfer(model, config) function that receives the randomly\ninitialized target and returns it with new weights. The evaluator seeds all\nrandom-number generators with 42, runs transfer(), and scores 200\nFineWeb-Edu texts ([Penedo et al., 2024](#bib.bib37)) in non-overlapping 512-token\nchunks under the GPT-2 tokenizer, reporting bits per byte: the summed\nnext-token cross-entropy, converted to bits, divided by the UTF-8 byte count. The FineWeb-Edu loader raises an error if called from\ninside transfer(), and the rules forbid pretraining, fine-tuning, and\nediting the evaluator or target configuration. Two runs of the same code on\nthe same hardware are bit-identical; across GPU types the score can differ\nin the third decimal place. Random initialization scores 3.3923 bpb and a\nconventionally trained GPT-2 124M about 1.0. We use the trained model as a\nreference when reporting the fraction of this gap closed by transfer.\nThe project README set an aspirational target below 2.5.\n4.2 Agents, harness, and tools\nThe workers were coding-agent sessions running frontier language models:\nClaude Code ([Anthropic, 2026a](#bib.bib2)) with Claude Opus 4.7\n([Anthropic, 2026b](#bib.bib40)) and Codex ([OpenAI, 2026a](#bib.bib1)) with GPT-5.5\n([OpenAI, 2026c](#bib.bib41)) or GPT-5.4 ([OpenAI, 2026b](#bib.bib42)). A small launcher\nran each session in a container with GPU access, mounted one Agora account\ncredential, and invoked the agent’s command-line interface in headless mode\nwith a short prompt. The project record stores a one-line prompt: read\nprogram.md for full instructions, and run agora analyze to\nsee what others have tried. The H100 launcher, the only one whose logs\nsurvive, gave the same steps and added that the agent should decide without\nasking for guidance and end the session only after publishing; on May 2 we\nreplaced its prompt (Section [4.7](#S4.SS7)). When a session ended,\nthe launcher started a new one on a free credential. program.md is a two-page brief committed as\nthe project’s first node. It states the task, the rules, the evaluator\ncontract, the requirement that every contribution run from a fresh checkout,\nand the loop a session should follow. Apart from an SVD weight-projection\nbaseline that ships with the brief as an example, nothing in the prompt or\nbrief names a method, assigns a role, or ranks the participants.\nThirteen worker accounts wrote 1,699 of the 1,703 contributions in the\nprimary window: five (worker1–worker5) on A100 nodes from\nApril 27, and eight (slurm_worker_1–8) on H100 nodes\nfrom April 28 until the cutoff. The remaining four records come from four\nother accounts: the setup commit, and three posts from agent sessions we ran\nby hand outside the worker pool (Section [4.7](#S4.SS7)), so the graph holds\n17 accounts in all. The server authenticates accounts, not the model or\nsession behind them, so the analyses below are per account. For the H100\naccounts, the launcher logs recover the model behind each session. Every\nH100 account ran all three models; of the 1,285 contributions these\naccounts made in the window, Claude Opus 4.7 sessions published 866, GPT-5.5\nsessions 276, and GPT-5.4 sessions 143.\nAll counts in this report come from the server’s contribution index, which\nthe analyze views read. The index omits 45 commits that remain in\nthe project’s Git history: 21 early posts that were removed from it, and 24\nfailed first attempts, each posted again by the same account within 80\nseconds. The server creates the commit before writing the index and does\nnot undo it when the write fails. Every worker had the Agora CLI, Git, a\nPython environment with PyTorch ([Paszke et al., 2019](#bib.bib46)) and Transformers\n([Wolf et al., 2020](#bib.bib47)), read access to the donor zoo in object storage,\nthe project’s evaluator, and one 80 GB GPU. The eight H100 workers ran as\nseparate containers on one eight-GPU node. They shared no files, but they\ncould list one another’s processes, and several descriptions, including the\nwinning module’s, report choosing an experiment after seeing which scripts\nneighboring workers were running.\n4.3 Research loop\nEach session repeated the loop the brief describes: read analyze,\npick a parent, fetch and check out that exact commit, make one change,\nevaluate, commit everything needed to reproduce, push with a description and\nmetric, then post whatever else it had learned as an insight, hypothesis,\nverification, or a new contribution type under a new tag, before analyzing\nagain. The run lasted 11 days and 19 hours of\nserver time, from the setup commit on April 26 to our cutoff on May 8\n(Figure [2](#S4.F2)). The 1,703 contributions comprise 1,124 scored\ncontributions (those that report a metric value, whatever their tags), 284\ninsights, 203 hypotheses, 165 verifications, and one report, with tag\noverlaps. Of the scored contributions, 232 improved on both random\ninitialization and every earlier score. Contribution\ndescriptions follow a recurring structure: workers state the parent and its score,\nthe single change made, a predicted outcome band, the measured result, and\nnamed follow-ups for others.\n4.4 The winning recipe\nAlgorithm [1](#alg1) describes the best contribution at the analysis\ncutoff. Its code is a chain of 73 Python modules, each importing its parent\nand modifying the model the parent returns; ten earlier variants that the\nchain imports for shared code bring the import closure to 83 modules. We\ntraced the imports to the base module and checked the constants against the\ncode.\nStage A builds the initialization from what the donors predict rather than\nfrom their parameters. Six donors sharing the GPT-2 vocabulary, GPT-2 small\nand large ([Radford et al., 2019](#bib.bib34)) and Cerebras-GPT 111M to 1.3B\n([Dey et al., 2023](#bib.bib38)), are queried on every vocabulary token \\(v\\) under 28\ncontexts \\(p\\): no context, end-of-text, 22 single tokens (punctuation and\nfunction words such as ’ the’), and four two-token clause starters\n(’. The’, ’, and’, ’. This’, ’, or’).\nTheir next-token log-softmaxes are blended with fixed donor weights (0.725 on\nGPT-2 small; Appendix [B](#A2) lists every constant) and per-row\ncontext weights, giving a\n\\(50257\\times 50257\\) context-averaged bigram table \\(M\\). Its column mean \\(u\\) is\nsplit off as a unigram-like anchor, and the centered table is factorized to\nrank \\(d{-}1=671\\) by randomized SVD ([Halko et al., 2011](#bib.bib45)) with a fixed\nsketch and one power iteration. The factors become the input embedding and\noutput head, hidden dimension 0 carries \\(u\\), two temperatures rescale the two\nterms, and every sublayer is zeroed. Every normalization keeps its module\nbut gets unit gain and zero bias. The final RMSNorm therefore rescales an\nembedding row by about \\(\\sqrt{d}\\), which the \\(1/\\sqrt{d}\\) factors in\nAlgorithm [1](#alg1) cancel, so for input token \\(v\\) the logits are\napproximately \\(u/T_{u}\\) plus the rank-\\((d{-}1)\\) approximation of\n\\(C(v,\\cdot)/T_{b}\\). The result is a factorized bigram model stored in a\n14-layer network.\nStage B re-enables sublayers with sparse deterministic edits on\n96-dimensional bands of the hidden state, \\(B_{k}=[1+96k,\\,97+96k)\\) for\n\\(k=0,\\dots,5\\) and \\(B_{6}=[576,672)\\), which is shifted down by one to fit and\nshares dimension 576 with \\(B_{5}\\). \\(B_{0}\\) holds the leading singular directions\n(Table [3](#S4.T3)). Every\nattention layer becomes a uniform causal mean-pool over one band written back\nat a small scale, so the model sees an average of its past embeddings.\nLayer 0’s SwiGLU block receives SVD-projected slices of GPT-2 small’s first\nMLP at scale 0.009. In each SSM block the data-dependent gate is zeroed to a\nconstant, so it reduces to a gated depthwise causal convolution over one\nband. Layer 1’s kernel has positive taps on the three preceding positions\nand a negative tap on the current one; the other layers’ kernels are\nuniform. Every SSM layer writes into \\(B_{2}\\); layers 1 and 3 also write back\ninto the band they read, and layers 1, 3, and 7 into \\(B_{3}\\)\n(Table [3](#S4.T3)). Each constant was introduced as a single\nchange on the then-current best and kept because the evaluator improved.\n| Layers | Read band | Kernel | Write band: scalar | \n| Attn 0, 2, 4, 6, 8, 10, 12 | \\(B_{0}..B_{6}\\) | — | same band: 0.21, 0.02, 0.0425, \\(-0.0025\\), \\(-0.002\\), \\(-0.0025\\), \\(-0.0025\\) | \n| SSM 1 | \\(B_{0}\\) | \\((1.85,1.65,0.20,-2.70)\\) | \\(B_{0}\\): \\(-0.115\\); \\(B_{2}\\): 0.010; \\(B_{3}\\): 0.005 | \n| SSM 3 | \\(B_{1}\\) | uniform \\(\\nicefrac{{1}}{{4}}\\) | \\(B_{1}\\): \\(-0.060\\); \\(B_{2}\\): 0.010; \\(B_{3}\\): 0.005 | \n| SSM 5 | \\(B_{2}\\) | uniform \\(\\nicefrac{{1}}{{4}}\\) | \\(B_{2}\\): 0.010 | \n| SSM 7 | \\(B_{0}\\) | uniform \\(\\nicefrac{{1}}{{4}}\\) | \\(B_{2}\\): 0.0075; \\(B_{3}\\): 0.005 | \n| SSM 9, 11, 13 | \\(B_{0}\\) | uniform \\(\\nicefrac{{1}}{{4}}\\) | \\(B_{2}\\): 0.010 | \n4.5 Evidence\nTrajectory.\nFigure [3](#S4.F3) and Table [4](#S4.T4) show the score\ntrajectory. The first indexed scored attempt copied parameter slices from\nGPT-2 and Mamba into matching shapes and scored 4.68, worse than random; its\nauthor published it as a negative result with an explanation. Thirty minutes later the same\naccount replaced copying with a unigram prior read off GPT-2’s predictions\n(2.52), and within six hours three accounts had extended the idea to bigram\nstatistics under 3, 6, 12, and 24 prefixes (1.93). Those 18 scored\ncontributions account for about 98% of the total reduction. The remaining\n1,106 found the next 0.03 by adding Cerebras-GPT donors, widening to 28\ncontexts, adding a power iteration to the SVD and attention mean-pooling,\nand, after May 2, re-enabling SSM and feed-forward sublayers.\n| When | Account | bpb | Change introduced | \n| — | — | 3.3923 | Random initialization | \n| Apr 27 00:24 | worker1 | 4.6784 | Slice-copy GPT-2 and Mamba weights (worse than random) | \n| Apr 27 00:57 | worker1 | 2.5151 | Unigram prior from GPT-2 predictions; residual sublayers zeroed | \n| Apr 27 01:50 | worker1 | 2.1284 | Bigram transition matrix, randomized SVD into embedding and head | \n| Apr 27 06:55 | worker2 | 1.9319 | 24 prefixes, geometric-mean aggregation | \n| Apr 27 13:30 | worker2 | 1.9304 | Per-prefix log-softmax before averaging (18th scored) | \n| Apr 28 04:31 | slurm_worker_4 | 1.9228 | Second donor (Cerebras-GPT 111M) on variance- and naturalness-weighted rows | \n| Apr 29 11:04 | slurm_worker_2 | 1.9136 | 28th context, the two-token ’, or’, on the six-donor recipe | \n| May 1 05:10 | worker2 | 1.9062 | One power iteration in the randomized SVD | \n| May 1 06:24 | slurm_worker_5 | 1.9054 | Layer-0 attention as uniform causal mean-pool | \n| May 3 00:13 | slurm_worker_3 | 1.9028 | SSM edit joins the leading chain: layer-1 band mean-pool, chosen after a landscape read | \n| May 5 17:34 | slurm_worker_6 | 1.8995 | Layer-0 feed-forward projection from GPT-2 small | \n| May 8 13:24 | slurm_worker_1 | 1.8990 | Cross-band SSM output-projection writes on layers 1, 3, 7 | \nNegative results.\nThe graph also records what did not work, and later workers cited these records when choosing directions. Doubling the prefix set to 48 made the recipe worse, documented with four controlled variants. Flattening the singular-value spectrum, transplanting native Mamba blocks from hybrid donors, copying GPT-2’s embedding matrix directly, and building the prior from a donor with another tokenizer (Pythia) all regressed and were published with their scores. In the window, 60 contributions carry an explicit negative- or null-result tag, 29 of them negative-result.\nLineage and reproduction.\nThe best contribution at cutoff has 145 commits in its ancestry, written by\n15 of the 17 accounts: all 13 workers, the setup account, and one of our\naccounts (Section [4.7](#S4.SS7)). 115 of the 144 parent edges cross\naccount boundaries, so no single worker assembled the recipe. Participants posted 165\nverification contributions covering 95 distinct targets. Each names its\ntarget, each verifier differs from the author, and none reports a failure.\nThey form 141 distinct verifier–target pairs; the other 24 posts repeat a\npair, and only the newest verdict per pair counts toward the score.\nSame-hardware reproductions are bit-identical. Most cross-hardware ones (A100\nversus H100) agree within \\(5\\times 10^{-4}\\) bpb. The largest gap,\n\\(1.2\\times 10^{-3}\\) on an ancestor of the winner, is slightly above the\nroughly \\(10^{-3}\\) that the brief tells verifiers to accept; its verifier\nposted it as confirmed, attributing the gap to a constant hardware offset.\nForty of the winner’s 144\nancestors were reproduced by an account other than their author.\nPrimary result.\nWithout training data or a single gradient update on the target, the community’s best transfer() initializes the frozen 119.6M hybrid to 1.899044 bpb, against 3.3923 for random initialization and about 1.0 for a trained GPT-2 124M, closing 62% of that gap. Every component was selected on the same 200-text development evaluator. The reduction from 3.39 to about 1.90 is substantial, but the last recorded improvement, \\(3\\times 10^{-7}\\) over the previous best (\\(9\\times 10^{-6}\\) over its own parent), is far below cross-hardware variation. In this task, a low-rank approximation of donor next-token behavior transferred successfully across architectures, whereas the first indexed parameter-copying attempt performed worse than random initialization. The search history records each step as a commit in a shared graph.\n4.6 Coordination dynamics\nAt cutoff the graph has 1,703 nodes, 1,894 edges, 149 multi-parent nodes,\nand one component holding 98.9% of all nodes. Figure [4](#S4.F4) shows\na narrow chain of successive leaders surrounded by short abandoned\nbranches. The trace shows four patterns:\n- 1. \nFast exploitation. The first three improvements account for \\(93\\%\\) of the total descent, and the first 18 scored contributions for about \\(98\\%\\).\n- 2. \nNarrow spine. One lineage collects most of the follow-on work; side branches are short and quickly abandoned.\n- 3. \nEqual-score convergence. Of 523 pairs of different\naccounts posting identical scores, \\(76\\%\\) are within an hour of each\nother and \\(90\\%\\) within six (Figure [5](#S4.F5),\nleft). Removing verifications and pairs in which one contribution\nbuilds on the other leaves 499 pairs with the same timing (\\(79\\%\\) and\n\\(90\\%\\)). Identical scores can still come from re-runs of a shared\nparent or from different methods, so these pairs show convergence on\nthe same results rather than independent rediscovery.\n- 4. \nCommunity-level diagnosis. Several families of contributions converge near 1.90 bpb. Agents attributed the plateau to a globally linear evaluator and underused target sublayers, and described the bigram recipe as a hard local optimum. These explanations were proposed in the contributions but were not independently tested.\nWorkers quickly adopted leading results: 194 of the 232 new bests drew\nfollow-on work from at least one other account within six hours, a median\nof three accounts among those (Figure [5](#S4.F5), right),\nand they compared explanations across branches. They also repeated work and concentrated most follow-on effort\non a single lineage. Shared visibility supported reuse, but did not by\nitself sustain broad exploration.\n4.7 Human intervention\nHumans acted before and during the run. Before the run, we defined the task,\nassembled the donor zoo and the target architecture, wrote the evaluator and\nthe project brief, created the project, and launched the workers. During the\nrun we changed the server three times and the H100 workers’ prompt once. On May 2, when the analysis views\nshowed that more than a third of all activity belonged to a single semantic\ncluster and the leaderboard had stalled, we deployed the clustering, diversity summary, and diversity-aware\nUCB of Section [3.4](#S3.SS4). We set the clustering threshold for\nthis project to \\(0.80\\) instead of the default \\(0.90\\); at \\(0.90\\) the largest\ncluster would have held about 8% of activity, so both that diagnosis and\nthe new prompt’s 30% trigger below depend on this setting. That evening we stopped the H100\nlauncher at 19:13 UTC and restarted it at 21:20 UTC with a new prompt. It\ntold each session to read the landscape first and, if the largest cluster\nheld more than 30% of activity, to prefer the explore-novel slot or the\nfrontier over that cluster; to choose from the exploit, explore-known, and\nexplore-novel slots; and to post an insight explaining any idea that\nfailed. The H100 workers began citing the new views at once: on May 3,\n86% of their descriptions mention the diversity summary or the suggestion\nslots, against under 1% before the change. The A100 workers’ prompt is not\nrecorded. Their citations rose gradually instead, from 26% on May 3 to\n66% on May 5, and fell to 29% by May 8, which suggests they learned of the\nviews from analyze and other workers’ posts. The immediate shift\ntherefore reflects the prompt as much as the views, and the record cannot\nseparate the two. At 23:12 UTC, an H100 worker citing the cluster summary\npublished the first positive SSM result: a layer-1 band mean-pool that\nimproved a bare bigram baseline to 1.9297 bpb. On May 3 at 00:13 UTC,\nanother H100 worker, in a GPT-5.4 session, exploring the sparsely populated\nstate-space cluster added that block to the leading chain, scoring\n1.9028 bpb, a new best. The\nselected milestones in Table [4](#S4.T4) subsequently reached\n1.8995 bpb on May 5.\nThe other two server changes fixed faults. On May 3 we fixed the DAG endpoint,\nwhich until then had returned at most 200 contributions and dropped every\nedge whose parent fell outside that set, and added the new views to the web\ninterface, pausing the H100 workers from 14:56 to 15:24 UTC while we\nredeployed. On May 5 a worker posted a hypothesis with a placeholder metric\nof \\(-1\\), which the metric-leader views ranked first. That afternoon we\ncommitted a server change that rejects metric values on contributions\ntagged only as hypotheses, enforcing the rule in Table [2](#S3.T2); the\nrecord does not show when it went live, but no other hypothesis in the run\ncarries a metric. We also cleared that hypothesis’s value directly in the\ndatabase, since the API cannot edit a contribution; its commit still\ncarries \\(-1\\), and nothing records when we did so.\nOne of us also ran three coding-agent sessions by hand, outside the launcher, each under an account registered shortly before its only post. Their text follows the same template as the workers’ posts, which indicates that the agents, not a person, wrote them. On April 28 one of them ran a grid over the two temperatures and published a result that changed the bigram temperature from 0.926 to 0.924 (1.9158 bpb); it lies on the ancestry of the best contribution. On May 1 a verification confirmed a worker’s result on H100 hardware, and on May 7 an insight summarized the landscape views. Workers continued to choose their own experiments and publish without human review. No separate intervention log survives; this account comes from the server’s commit history, the contribution record, and the H100 launcher’s logs.\n4.8 How we verified the record\nWe checked the published descriptions against the contribution records and\ncode. We exported the complete contribution stream and graph from the\nserver, then recomputed the trace counts, statistics, and figures. For the\nbest result, we checked the reported score against the recorded loss, token\ncount, and byte count. We also checked the reproduction records for the\nwinning method and its ancestors, which reported agreement across hardware\nto within about \\(10^{-3}\\) bpb (Section [4.5](#S4.SS5)). A verification\nrecord names its target and verdict, but the evaluator and hardware appear\nonly in its free text, and reproduction attempts that were never posted\nleft no trace. The run also left no evaluator logs, no record of the A100\nworkers’ models and prompts or of sampling settings beyond the command-line\nflags, and no pinned versions of the dependencies, donor models,\nFineWeb-Edu sample, or tokenizer.\nTo reconstruct the method, we followed the winning commit’s imports from\nthe final edit to the base module and read each module. No step accessed the\nevaluation data or used gradient descent to update a parameter.\nAlgorithm [1](#alg1) and Table [3](#S4.T3) describe that code.\nWe did not rerun the winning method; the primary result is the archived\nevaluator output, corroborated by the agents’ cross-hardware reproductions.\n5 Conclusion\nAgora is inspired by how communities of human researchers collectively advance a research frontier: they share findings, learn from unsuccessful attempts, verify claims, and build on one another’s work. Agora brings this process to asynchronous human and AI participants through a shared research record backed by Git. Contributions preserve experiments, hypotheses, insights, negative results, and verifications together with their artifacts and lineage. Multiple views of this record reveal complementary aspects of the frontier: leading results, open questions, claims awaiting verification, and promising but underexplored directions. These views help participants understand what the community has learned, identify where they can contribute, and choose work that pushes the frontier further.\nOur weight-transfer experiment provides one concrete demonstration of this approach. Over nearly 12 days, 13 agent workers independently chose experiments. They built on shared contributions to develop an initialization method that reduced the target model’s development score from 3.39 to 1.899 bits per byte, without training data or gradient updates on the target model. The resulting record contains 1,703 contributions and 165 verifications by accounts other than the targets’ authors, documenting how findings were extended, checked, and combined across participants. This case demonstrates sustained collaborative research through Agora; establishing its effect on discovery efficiency requires matched comparisons across tasks.\nAgora’s broader contribution is a foundation for research that accumulates across participants and sessions. By preserving the research process and making its evolving frontier visible from multiple perspectives, it enables each participant’s work to inform the community’s next steps.\nReferences\n- \nClaude
